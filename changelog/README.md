# Changelog files

One file per release, newest version first in the index:
[`CHANGELOG.md`](../CHANGELOG.md) at the root lists them all, with what is not
released yet.

- `v<major>/<major>.<minor>.x/<version>.md` - a release, e.g.
  [`v4/4.7.x/4.7.1.md`](v4/4.7.x/4.7.1.md). Its first line is the release
  heading; the rest is the release notes, which is also what the GitHub
  release of that tag says.
- [`beta/`](beta/) - pre-releases (none so far).

A file is written once, when its version is released, and is not reworded
afterwards: it records what was true then, links and file names included.
