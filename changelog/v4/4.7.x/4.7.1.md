# v4.7.1 – 2026-11-09 (The "Curb Cut" Edition)

[All versions](../../../CHANGELOG.md)

An accessibility release. The repository gains an accessibility statement
that says honestly what works with a keyboard, a screen reader and zoom, and
what does not yet. The worst barriers it found are fixed:
- the games table is a real table to a screen reader;
- the first-run screens hold the keyboard focus;
- kernel-level anti-cheat is no longer told apart by colour alone;
- both themes meet the contrast WCAG asks for;
- the desktop app zooms.

Like a curb cut, most of it helps everyone. The community docs were also
brought back in line with the repository. No legal document you accept
changed, so nobody is asked to accept the terms again.

Desktop and Android go from `2.5.0` to `2.5.1`, and the repo's public version
from `4.7.0` to `4.7.1`. The desktop app offers 2.5.1 through its updater once
the release is published. On Android, install the new APK over the old one.

## ✨ Added

- **An accessibility statement.** `ACCESSIBILITY.md` says what works today
  with a keyboard, a screen reader and zoom, and what does not work yet: the
  games table, most charts, the first-run screens, zoom in the apps. It also
  lists which browsers and apps are checked by hand, and how a report is
  handled. GitHub shows it as the repository's Accessibility tab. Barriers get
  their own issue form and an `accessibility` label, and the About page links
  the statement and the form.
- A pull request template covering what and why, the checks to run, and a
  short accessibility list for interface changes.

## 🐛 Fixed

- The About page's stack list said SvelteKit 2 and counted 3,600 rows. Its
  footnote said everything the page loads comes from this site, which is not
  true of Cloudflare's beacon and human check. It now says what is true: the
  game data and art come from this site. The Vietnamese AI note gains the
  sentence it was missing.
- Source archives (`git archive`, GitHub's "Source code" downloads) left out
  three legal documents that the web build reads, so building from one
  stopped. They are included now.
- **Accessibility**, on the website and in the apps from 2.5.1:
  - **The games table** is now a table to a screen reader. It exposes its
    roles, the row and column counts, and a position for every row, even
    though only the rows on screen exist. The image, data-issue and Steam
    columns have names.
  - **Table rows** are no longer a link wrapped around another link, and each
    row is one <kbd>Tab</kbd> stop instead of two. Clicking anywhere on a row
    still opens the game.
  - **The phone cards** are a list that tells a screen reader its length and
    each card's position.
  - **The terms screen and the human check** are dialogs that take focus, and
    the page behind them is out of reach until you are through. Before, Tab
    walked through the hidden page first, and Ctrl/⌘+K could open the
    command palette underneath them, out of sight but holding focus.
  - **Kernel-level anti-cheat** shows a shield icon and the words, not only a
    red badge.
  - **Contrast:**
    - Light-theme links, primary buttons, warnings and badges reach 4.5:1.
      The light theme's amber is a shade darker as a result.
    - Red badges in the dark theme reach 4.5:1 too.
    - Text boxes and drop-downs have a visible 3:1 edge in both themes.
  - **Zoom:**
    - The games list keeps a minimum height when zoomed in, instead of
      shrinking to nothing at 300-400%.
    - The desktop app zooms with Ctrl/⌘ and + / −.
  - **Smaller fixes:**
    - "Back to top" is out of the Tab order while it is hidden, and jumps
      instead of gliding when *reduce motion* is on.
    - The command palette's search box shows a focus ring.
    - Screen readers read out the 💀 and the table's warning icon as words.
  - `ACCESSIBILITY.md` moves all of this from "Known limitations" to "What
    works today".

## 🧰 Tooling & misc

- `web/src/lib/a11y.test.ts` holds those fixes in the code. It also computes
  the theme's contrast with the WCAG formula, so a colour edit that drops
  below 4.5:1 for text, or below 3:1 for a control's edge, fails the tests.
